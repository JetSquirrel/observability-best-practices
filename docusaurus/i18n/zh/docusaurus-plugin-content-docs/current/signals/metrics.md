# 指标

指标是一系列按照创建时间顺序排列的数值数据。它们用于跟踪从环境中服务器的数量、磁盘使用情况、每秒处理的请求数量，到完成这些请求的延迟等各种数据。

指标不仅限于基础设施或应用程序监控。它们可以用于任何类型的业务或工作负载，用来跟踪销售情况、呼叫队列和客户满意度。事实上，当将运营数据和业务指标结合使用时，指标的价值最大化，因为这样可以提供一个全面的视角和可观测的系统。

可以参考 [OpenTelemetry 文档页面](https://opentelemetry.io/docs/concepts/signals/metrics/)，了解更多关于指标的内容。

## 了解关键绩效指标(KPIs)，并对其进行测量！

*最*重要的是要测量*正确的事物*。对于每个人来说，这些事物都是不同的。例如，电子商务应用程序可能将每小时销售额作为 KPI，而面包店可能更感兴趣的是每天制作的可颂数量。

:::warning
对于业务关键绩效指标（KPI）来说，并没有一个单一的、完全完整和全面的来源。你必须充分了解你的项目或应用程序，才能明确你的*输出目标*是什么。
:::

你的第一步是确定高层次目标，这些目标很可能不仅仅是通过基础设施获得的单一指标来表达。在前文中提到的电子商务的例子中，一旦你确定了衡量*每小时销售额*为*元*目标，你就可以回溯到更详细的指标，比如在购买前产品搜索所花时间、完成结账流程所需时间、产品搜索结果的延迟等。这将指导我们有目的地收集相关信息来观察这个系统。

:::info
在确定了 KPI 之后，你现在可以*逆向思考*来查看工作负载中哪些指标会影响它们。
:::

## 与运营指标数据相关联

如果Web服务器的高CPU使用率导致响应时间变慢，进而使客户不满意并最终降低收入，那么测量CPU使用率就会直接影响您的业务成果，因此*绝对*应该进行测量！

相反，如果您有一个在临时云资源（如Amazon EC2机群或其他云提供商环境中的类似资源）上执行批处理的应用程序，那么您可能*希望*CPU尽可能得到充分利用，以便以最具成本效益的方式完成批处理。

在这两种情况下，您都需要将运营数据（例如CPU使用率）与业务指标放在同一个系统中，以便能够将两者关联起来。

:::info
将您的业务指标和运营指标存储在同一个系统中，这样您就可以将它们关联起来，并根据观察到的对两者的影响得出结论。
:::

## 了解什么是好的表现！

理解什么是健康的基准可能具有挑战性。许多人必须对他们的工作负载进行压力测试，以了解健康的指标是什么样的。但是，根据您的需求，您可能可以观察现有的运营指标，以得出关于健康阈值的安全结论。

健康的工作负载是在满足您的KPI目标的同时，保持弹性、可用性和成本效益的平衡。

:::info
您的KPI*必须*有一个确定的健康范围，这样您就可以在性能低于或高于要求时创建[告警](../signals/alarms/)。
:::

## 使用异常检测算法

[了解什么是好的表现](#了解什么是好的表现)的挑战在于，可能无法实际知道系统中*每个*指标的健康阈值。关系数据库管理系统(RDBMS)可以发出数十个性能指标，当与微服务架构结合时，可能会有数百个可能影响KPI的指标。

对于人类来说，观察如此大量的数据点并单独识别它们的上下阈值可能并不总是实际的。但机器学习在这种重复性任务中*非常*擅长。尽可能利用自动化和机器学习，因为它可以帮助识别您原本甚至不知道的问题！

:::info
使用机器学习算法和异常检测模型来自动计算您的工作负载的性能阈值。
:::
